# fs-pipeline-dart

> DART 전자공시에서 상장사 연결재무제표를 자동 수집·표준화해, 이후 모든 분석 프로젝트가 같은 숫자를 쓰게 하는 재무 데이터 레이어.

## 1. 문제 정의

재무 분석은 숫자를 옮겨 적는 데서 시작하고, 틀린 숫자는 대개 여기서 들어온다. 회사마다 계정과목명이 다르고, 연결과 별도가 한 응답에 섞여 있으며, 정정공시가 있으면 같은 기업·연도에 값이 두 개가 된다. 이 차이를 매번 사람이 맞추면 분석마다 기준이 달라진다.

이 레포는 KOSPI200 기업의 2015~2025년 연결재무제표를 DART에서 받아 표준 계정으로 정리하고, 다른 프로젝트(팩터 백테스트, DCF, 신용위험 등)가 DART를 다시 긁지 않고 import해서 쓰는 로더를 제공한다.

**성공 기준:** 무작위 표본 20건(기업×연도)의 매출액·영업이익·자산총계가 DART 공시 원문과 100% 일치한다.

**범위**

| | 내용 |
|---|---|
| Must | KOSPI200 × 2015~2025년(11개년) 연결재무제표(XBRL 전체 계정) 수집 · 계정과목 표준화 사전 · 재무비율 30종 · 표본 대조 검증 · 다른 레포용 로더 함수 · `analyze()` 진입 함수 |
| Should | 정정공시 반영 · 결산월 변경 기업 처리 · parquet 캐싱 · 주석 표 파싱 1건 시험 |
| Won't | 코스닥 · 분기 데이터 · 별도재무제표 · 실시간 갱신 · 웹 UI |

v0는 5개 기업 × 3개년으로 끝까지 관통한 뒤 확장한다.

## 2. 접근

- OpenDART의 **단일회사 전체 재무제표 API**(`fnlttSinglAcntAll`)를 쓴다. 주요계정 API는 계정 수가 적어 팩터와 비율 30종을 만들 수 없다.
- 계정은 이름이 아니라 **XBRL 표준계정ID**로 식별한다. 같은 영업이익도 회사마다 "영업이익", "영업이익(손실)"으로 다르게 적는다.
- 원본 JSON은 그대로 보관하고, 가공 결과는 parquet로 저장한다.

## 3. 회계·재무적 판단

요약이다. 판단마다 근거·대안·날짜는 [DECISIONS.md](DECISIONS.md)에 있다.

| 번호 | 판단 | 선택 |
|---|---|---|
| D-001 | 연결 vs 별도 | 연결재무제표. 별도는 연결실체 내부거래가 제거되지 않아 실적 자료로 쓰면 오류가 생기기 쉽다 |
| D-002 | ROE 분자·분모 | 귀속 범위를 맞춘다. 기본은 지배주주 순이익 ÷ 평균 지배지분(전기는 같은 보고서 비교 값), 연결 짝은 보조 |
| D-003 | 계정 식별 | 계정명이 아니라 XBRL 표준계정ID + 재무제표 구분 |
| D-004 | 정정공시 | 최종 정정본. 다음 해 재작성은 오류수정만 반영 |
| D-005 | 계정 표준화 | 비율 입력 계정만 표준화, 해마다 바뀐 ID는 묶음 표(비율 계정은 승인), 표준 계정별 부호 규칙(양방향 계정은 같은 해 증거로만), 영업수익 형식은 산식으로 식별 |
| D-006 · D-007 | 기준서 전환(1116·1117호) 비교가능성 · 판관비 분류 | 원래 값 + 단절 표, 단절 걸친 증감률은 NaN + 사유 · 판관비율은 기능별 양식만, 단일 영업비용 회사는 영업비용률 |
| D-009 · D-013 · D-014 | 금융업 XBRL 공백 | 2022 이전은 사업보고서 원문을 직접 파싱. XBRL 있는 해에 금액 전액 일치를 확인한 뒤 적용 |
| D-010 · D-015 | 금융업 | 매출 대신 총영업이익·CIR, 업종 양식(일반·금융지주). 표본 대조는 순이자이익 |

진행 단계는 [ROADMAP.md](ROADMAP.md), 구조는 [ARCHITECTURE.md](ARCHITECTURE.md), 변경 내역은 [CHANGELOG.md](CHANGELOG.md).

## 5. 검증

- 무작위 표본 20건(시드 기록) + 경계 사례(정정공시·결산월 변경) 1건 이상을 공시 원문과 대조한다. 기록은 `docs/validation.md`.
