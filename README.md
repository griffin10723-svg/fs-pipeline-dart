# fs-pipeline-dart

> DART 전자공시에서 상장사 연결재무제표를 자동 수집·표준화해, 이후 모든 분석 프로젝트가 같은 숫자를 쓰게 하는 재무 데이터 레이어.

## 1. 문제 정의

재무 분석은 숫자를 옮겨 적는 데서 시작하고, 틀린 숫자는 대개 여기서 들어온다. 회사마다 계정과목명이 다르고, 연결과 별도가 한 응답에 섞여 있으며, 정정공시가 있으면 같은 기업·연도에 값이 두 개가 된다. 이 차이를 매번 사람이 맞추면 분석마다 기준이 달라진다.

이 레포는 KOSPI200 기업의 최근 5개년 연결재무제표를 DART에서 받아 표준 계정으로 정리하고, 다른 프로젝트(팩터 백테스트, DCF, 신용위험 등)가 DART를 다시 긁지 않고 import해서 쓰는 로더를 제공한다.

**성공 기준:** 무작위 표본 20건(기업×연도)의 매출액·영업이익·자산총계가 DART 공시 원문과 100% 일치한다.

**범위**

| | 내용 |
|---|---|
| Must | KOSPI200 × 최근 5개년 연결재무제표(XBRL 전체 계정) 수집 · 계정과목 표준화 사전 · 재무비율 30종 · 표본 대조 검증 · 다른 레포용 로더 함수 · `analyze()` 진입 함수 |
| Should | 정정공시 반영 · 결산월 변경 기업 처리 · parquet 캐싱 · 주석 표 파싱 1건 시험 |
| Won't | 코스닥 · 분기 데이터 · 별도재무제표 · 실시간 갱신 · 웹 UI |

v0는 5개 기업 × 3개년으로 끝까지 관통한 뒤 확장한다.

## 2. 접근

- OpenDART의 **단일회사 전체 재무제표 API**(`fnlttSinglAcntAll`)를 쓴다. 주요계정 API는 계정 수가 적어 팩터와 비율 30종을 만들 수 없다.
- 계정은 이름이 아니라 **XBRL 표준계정ID**로 식별한다. 같은 영업이익도 회사마다 "영업이익", "영업이익(손실)"으로 다르게 적는다.
- 원본 JSON은 그대로 보관하고, 가공 결과는 parquet로 저장한다.

## 5. 검증

- 무작위 표본 20건(시드 기록) + 경계 사례(정정공시·결산월 변경) 1건 이상을 공시 원문과 대조한다. 기록은 `docs/validation.md`.
