# 인계: 원문 파서 (새 세션 시작용)

작성 2026-10-03. 이 문서는 새 세션이 앞 세션의 맥락 없이 바로 시작하도록 쓴 것이다. 결정은 `DECISIONS.md` D-009·D-012·D-013이 원본이다.

## 시작 방법

- 레포 루트(`~/quant/fs-pipeline-dart`)에서 세션을 연다. 설정은 시작 폴더에서만 읽는다.
- `/model opus`, `/effort medium`으로 시작한다(`forge:dev-flow` 5-0절: 새 모듈 설계는 deep 역할). medium에서 막힐 때만 high.
- 첫 일은 코드가 아니라 **설계**다. `forge:dev-flow` 설계급 경로로 가고, 설계를 작업자가 승인하기 전에는 코드를 쓰지 않는다.

## 목표

DART 사업보고서 원문(`document.xml`)에서 재무제표 표를 읽어 D-011 스키마 DataFrame으로 내는 파서. XBRL이 없는 금융업 2019~2022와, 이후 M1·N2·P7이 쓸 주석 표 파싱의 기초 도구다.

## 정해진 것

- 직접 구현한다. `dart-fss`는 **독립 기준값(L2)과 참고 구현**이다. 파서가 `dart-fss` 출력을 입력으로 쓰지 않는다(오염 방지). `dart-fss`는 비교용 선택 의존성으로만 둔다.
- 파싱 행에는 `source` 컬럼(`document`)을 단다. XBRL 행은 `xbrl`. 섞어 쓰지 않는다.
- 실패는 조용히 넘기지 않는다. 표를 못 찾거나 항등식이 어긋나면 예외.
- 2019~2022 금융업에 적용하기 전 조건: 2023~2025 구간에서 파서 결과가 XBRL 값과 일치(D-013).
- Stage 1 게이트(표본 20건 대조)는 이 작업과 별개로 여전히 필요하다.

## 실측으로 알게 된 것 (2026-10-03, KB금융 `00688996`)

- 재무 API(`fnlttSinglAcntAll`·`fnlttSinglAcnt`·`fnlttMultiAcnt`)는 2022에 보고서 종류 4가지 × CFS·OFS 8조합 모두 `013`.
- 2022 사업보고서 공시 3판: `20230316001417`(원공시) · `20230324001073`(정정) · `20231005000471`(정정). 세 판 모두 자산·부채·자본총계가 같았다.
- `document.xml` 응답은 zip 안에 xml 1개. 9.7MB, 표 약 2,200개, 단위 표기 십여 가지(억원·십억원·백만원·원·조원 등).
- 자산·부채·자본총계를 모두 가진 표가 9개다. 연결 표는 1개이고 나머지는 자회사·부문 표다. 연결 표 값: 자산 701,170,848 / 부채 651,527,934 / 자본 49,642,914(백만원), 항등식 차이 0.
- 2022 원래 자산총계 701.17조원, 2023 보고서 전기 열은 688.66조원. 1117호 소급재작성 차이 약 12.5조원(D-004·D-009 판단의 실제 수치).
- 본문 표에는 `account_id`가 없다. D-003을 그대로 못 쓰고 계정명 매핑이 필요하며 D-005와 이어진다.
- `dart-fss` 0.4.17: `Corp(corp_code=...).extract_fs(bgn_de, end_de, fs_tp=("bs",), separate=False, report_tp="annual")`. 재무상태표는 성공(KB FY2022, 위와 같은 값). 손익계산서(`is`)는 `None`이 나왔고 원인은 조사하지 않았다. 의존 패키지 39개(arelle 등)가 딸려 온다. `uv run --no-project --with dart-fss`로 격리해 시험했다.
- `kordoc`은 HWP·PDF·DOCX·XLS용이라 DART 원문에 맞지 않는다.

## 열린 질문 (작업자 확인 필요)

1. 시간 상한. 앞 세션은 3일을 제안했다. 상한 안에 2023~2025 XBRL 일치까지 못 가면 D-009 Won't를 유지한다.
2. 첫 대상 범위: 연결 재무상태표만 / 손익 포함 / 주석 표 1건.
3. 표본 20건 구성 B(비금융 4사 2021·2022 추가, 풀 23건)와 시드 값은 Stage 1 게이트 쪽 결정이다.

## 설계 때 짚을 것

- 표 위치 찾기: 요약재무정보가 아니라 "연결재무상태표" 섹션 제목 기준. 단위는 표 앞 `(단위: …)`.
- 검증 기준: XBRL(2023~2025)과 전액 일치, 항등식, `dart-fss` 대조. 셋 중 어느 것이 L2인지 `forge:dev-rules` 3장 기준으로 정한다.
- 정정공시: D-004대로 최종 정정본의 접수번호를 쓴다. `collect.last_rcept_no`를 재사용할 수 있다.
- 새 파일은 `src/fs_pipeline_dart/` 아래. `dart.py`(API)·`collect.py`(저장)·`validate.py`(불변식)는 건드리지 않고 끝까지 가능한지 먼저 본다.
